Methodology. "Training throughput" and "GPU setup" are quoted directly from the source when the project reports them. "Est. training GPU-hours" is only quoted directly when the source states it explicitly; otherwise it's computed as GPU count × wall-clock training time and marked "computed" so it's clear it's a derived estimate, not a reported figure.

TinyLlama. GPU-hours are computed (16 × 90 days × 24h = ~34,560). The paper independently reports 3,456 GPU-hours for a 300B-token subset on the same hardware, which scales linearly to ~34,560 GPU-hours for the full 3T-token run — consistent with the computed figure above.

ProLong. Unlike TinyLlama, ProLong's paper (Table 9) states GPU-hours directly per stage, so no computation was needed there. Throughput figures here are back-computed from those reported GPU-hours (tokens ÷ GPU-hours); the paper separately reports per-device throughput for its 64K-stage ablation runs (Table 15: 2,770–3,095 tok/s/GPU depending on optimizations), which brackets the computed 64K figure above. The 512K stage is far slower per-GPU because distributed (sequence-parallel) attention is only engaged at that length. SFT (1B tokens on UltraChat) is included in the token count above but not in the 14,400 GPU-hours figure, since the paper doesn't state GPU-hours for the SFT stage separately.

OLMo 3. GPU counts and token counts per stage are quoted directly from the official model card (OLMo-core repo). GPU-hours (~234K for 7B, ~1.05M for 32B) and throughput (7,700 / 1,900 tok/s/GPU) are reported directly by Ai2 for the pretraining (stage 1) run only — midtraining and long-context-extension GPU-hours haven't been disclosed, so the totals above understate full training compute. Ai2 also reported average power draw of ~621W (7B) / ~649W (32B) during pretraining, working out to roughly 146 MWh and 681 MWh of energy respectively, and noted the 32B pretraining run took about 56 days wall-clock on the 1024-GPU cluster.

DCLM. DataComp-LM (DCLM) isn't a single released model like the other rows — it's a benchmark framework for comparing dataset curation strategies on equal footing. Participants filter or mix a shared Common Crawl pool, then train a fixed open_lm-based recipe at one of five standardized compute scales (400M-1x through 7B-2x), where "1x" targets roughly Chinchilla-optimal token counts and "2x" trains on twice that many tokens for the same model size. The three rows above are DCLM's own published reference training costs for the 400M-1x / 1B-1x / 7B-1x scales (from the project README's training-time table), not the results of one specific submission — any dataset trained with the standardized recipe at a given scale costs roughly the same compute, since architecture, sequence length (2048 tokens), and global batch size are fixed per scale. "Pool size" (the raw, unfiltered candidate pool a participant filters down from to reach the scale's target token count) is noted per row but isn't a site-wide column. GPU node counts per scale aren't stated in DCLM's release, only total H100-hours, so "Training throughput" above is an aggregate rate (tokens ÷ H100-hours) rather than a per-GPU figure. DCLM's own best submission from this process, DCLM-Baseline, became a released 4T-token open dataset; the flagship models DCLM separately trained on it at non-benchmark scale (e.g. apple/DCLM-7B, 2.5T tokens) aren't included here since they fall outside the 5 standardized track scales.

GPT-3. Params and tokens come directly from Appendix D of the GPT-3 paper itself ("Total Compute Used to Train Language Models," supporting Figure 2.2) — not a third-party source. Unlike every other row on this page, GPU count and wall-clock/throughput are genuinely undisclosed by the source, so "Est. training GPU-hours" here isn't computed from a reported GPU count or wall-clock time (as for TinyLlama) — it's estimated by assuming a throughput figure (28 TFLOPS/V100 effective) that nobody at OpenAI confirmed, the same assumption Lambda Labs used to independently publish "355 GPU-years" for the 175B run, which matches the figure above almost exactly as a cross-check. Treat the GPU-hours figures on these two rows as considerably softer than the rest of the table.

Sources: TinyLlama GitHub repo and the TinyLlama paper (arXiv:2401.02385); ProLong GitHub repo and the ProLong paper (arXiv:2410.02660); the OLMo 3 official model card (OLMo-core repo), the Ai2 OLMo 3 blog post, and Muxup's Olmo 3 training cost minipost; the DCLM GitHub repo and the DataComp-LM paper (arXiv:2406.11794); the GPT-3 paper (arXiv:2005.14165, Brown et al. 2020) and Lambda Labs' GPT-3 compute estimate.
